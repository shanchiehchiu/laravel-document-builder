# 設計器元件面板：待辦

來源：對元件面板的 UI 審查。下列項目已對照 `resources/dist/designer.js` 與 GrapesJS 樣式確認，狀態標註為「已確認」者表示問題存在。

## 一、圖示變成實心黑塊（高優先）

- [x] **已確認**：GrapesJS 的 `.gjs-block svg{fill:currentColor}` 會蓋過 `icon()` 的 `fill="none"` 屬性，子元素繼承後變成實心。
- 做法：在設計器樣式中，把 `#wfb-blocks svg { fill: none; }` 與 `#wfb-blocks svg * { fill: none; }` 限定在元件面板內，避免影響其他區域。

## 二、圖示語意化

- [x] **已確認**：主檔來源沒有對應圖示（例如 `user`、`leave`）時，會退回 `ICONS.field`，即三條橫線，與「說明文字」撞圖。
- [x] 為常用主檔來源補上獨立圖示（使用者：頭像；員工：識別證；請假紀錄：日曆加時鐘）。
- [x] 主檔積木加上小型「鏈結」標記（左上角，CSS `::after`，積木 class 為 `wfb-block-master`），區分靜態欄位與關聯主檔。

## 三、資訊架構

- [x] **已確認**：「明細表」目前在「排版」分類（`designer.js:1000`）。建議把排版改名為「輔助排版」，明細表獨立為「表格／容器」分類。
- [x] 主檔下拉的擴充：採用方案 A。
  - 面板只剩一張「主檔關聯」積木（`master-link`），不再為每個來源建立積木。
  - 拖入後來源留空，欄位被選取，焦點自動移到右側「主檔來源」下拉。
  - 選定來源後，若欄位名稱仍是預設的「主檔關聯」，會改用來源名稱；使用者改過的名稱不覆寫。
  - 畫布上的主檔欄位標記帶來源小圖示，來源的語意由欄位卡片呈現。
  - 存檔前會檢查：仍有來源為空的主檔欄位（表頭與明細表都檢查）時，不送出，提示並選取該欄位。後端原本也會擋（`config/form_platform.php` 的 `source` 為必填），但錯誤訊息不指出是哪一欄。
  - 來源庫同步只更新來源清單，不再增刪積木。
  - 驗證：headless Chrome 載入真實的 `designer.js`（由測試產生的設計器頁面），13 項檢查通過。
  - 方案 B（搜尋框）未採用。
- [ ] 依賴：「建議價來源」的 (A)/(B) 決定仍未定，與主檔關聯無直接衝突，但之後的換算組會用到主檔欄位時要再確認。

## 四、補齊業務元件（依優先序）

- [ ] **金額／貨幣**：千分位、小數位、幣別符號。
- [ ] **計算／公式**：與待辦中的「換算組」與「伺服器端重算」相關，應一併設計，不要各自實作。
- [ ] **單選按鈕組**：選項少時比下拉更直觀。

- [ ] **日期區間**、**附件**、**簽名**、**分隔線**：依實際表單需求排序。

## 五、排版與互動

- [x] 卡片文字過長時加上 `text-overflow: ellipsis`；完整名稱由 GrapesJS 預設的 `title` 提供（已確認，不需另外設定）。
- [x] 卡片 hover 時顯示 `cursor: grab`（拖曳中為 `grabbing`）。
- [x] 拖曳把手紋路：卡片右上角六點圖示（CSS `::before` 實作，平時淡化、hover 加深）。
- [x] 水平卡片版型＋單張卡片跨欄：分類裡只有一張積木時（目前是主檔關聯、明細表），卡片跨滿整列，改成圖示左、文字右，避免 3 欄網格留下空格。
  - 問題來源（真實設計器截圖與 DOM 量測）：面板為 3 欄 CSS Grid，各分類積木數為欄位 6、主檔下拉 1、輔助排版 3、表格 1，主檔下拉與表格右側各空 2 格。
  - 實作只改 CSS（`:only-child` 選擇器），DOM 結構不變；鏈結標記在水平版型下改到左下角，避免和圖示重疊。
  - 驗證：真實設計器頁面重新截圖，兩個單張分類已跨欄並靠左對齊，其他分類不受影響。
  - 注意：這個規則只對「分類裡唯一的一張積木」生效。之後若主檔下拉或表格加入第二張積木，會自動回到 3 欄直式卡片。
- [x] 已封存分類的「折疊計數標籤」：已實作。分類標題為「已封存（N）」，N 為封存的欄位與明細表數量（`designer.js` 的 `archivedLabel`），分類可摺疊。原先這一項被標為未實作，是文件錯誤，已更正。

1. 圖示實心黑塊（改動小、影響大）
2. 主檔圖示補齊與語意化
3. 拖曳提示與文字溢出處理
4. 明細表分類調整
5. 業務元件與主檔關聯（需與待辦中的換算組、建議價來源一起規劃）
